## Aktuelle Seitenstruktur

- `Start`: Einstieg, Scope und Pflegehinweise für die Dokumentationsfläche
- `Produkt`: Produktlogik, Rollen, Kernobjekte und gewünschter Betriebsablauf
- `Backend`: Architektur, API-Oberfläche, Berechtigungen und Runbook

## Quellenlage

- Die Produktabsicht kommt aus dem PRD im Repository-Root.
- Die Backend-Details kommen direkt aus `backend/src`.
- Dieses Storybook soll den tatsächlichen Ist-Zustand beschreiben, nicht ein Wunschbild.

## Nächste sinnvolle Ausbaustufen

1. Reale UI-Komponentenstories ergänzen, sobald das Frontend über den Starterzustand hinausgewachsen ist.
2. Sequenzdiagramme für Intake, Freigaben, Erinnerungen und Agent-Vorschläge ergänzen.
3. Betriebsdokumentation für Deployment, Migrationen und Token-Rotation ergänzen.

## Qualitätssicherung

- `npm run docs:audit` prüft Drift zwischen Backend-Code und Dokumentation.
- `npm run docs:check` kombiniert Audit und produktiven Storybook-Build.
- Der CI-Workflow im Repository führt denselben Docs-Check bei Pushes und Pull Requests aus.
