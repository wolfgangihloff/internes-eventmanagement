## Interaktionsfluss

1. `main.tsx` bootet React und rendert `App`.
2. `App.tsx` erstellt den Router und hängt den `QueryClientProvider` um die Anwendung.
3. `ProtectedLayout` prüft, ob ein Nutzer im Auth-Store liegt.
4. Feature-Hooks nutzen `apiClient` mit automatisch angehängtem Access-Token.
5. Bei `401` versucht der Client einen Refresh; schlägt der fehl, erfolgt Logout und Redirect auf `/login`.

## Relevante Grenzen

<Callout title="Worauf man im Frontend aktuell achten sollte" tone="warning">
  <ul>
    <li>
      Die Dokumentation deckt die Anwendungsarchitektur ab, nicht jede einzelne
      UI-Komponente. Klassische Storybook-Component-Stories sind weiterhin nur
      als Starter-Beispiele vorhanden.
    </li>
    <li>
      Die Session-Wiederherstellung ist bewusst browserseitig mit `zustand`
      modelliert. Das ist pragmatisch für die Demo, aber kein vollwertiges
      Security-Konzept für höhere Anforderungen.
    </li>
    <li>
      Rollenlogik existiert doppelt: als UI-Gates im Frontend und als
      durchsetzende Autorisierung im Backend. Das Backend bleibt die letzte
      Instanz.
    </li>
  </ul>
</Callout>
